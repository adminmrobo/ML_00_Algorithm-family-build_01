The Reinforcement House — Try It, Learn from the Reward

A robot vacuum has no answer sheet saying "in this square, go left". Instead there are rewards, like +1 for picking up dust and −1 for bumping a wall. It tries something, gets the result, and next time picks something a little better.

This is reinforcement learning. Instead of a teacher giving answers, it finds on its own a way of acting (a policy) that makes the total reward large. And one dilemma always comes along: pick the option that looks best right now, or try the unknown one once more?

01
The loop

The Reinforcement Learning Loop — Act, Get a Reward, Repeat

Agent → action → environment → state and reward → agent

Animation · one round with the lowest-ranking member, Sweepy (a cleaning bot)

Updating the value: subtract the expectation from the result, and add just a little

For each action, Sweepy keeps a value Q: "about how much will I get if I do this?". On receiving reward r, Q ← Q + α(r − Q). If the result (r) beats the expectation (Q), the value goes up; if it's worse, it goes down. α is the learning rate, which sets how much to correct at once. This episode's showdown runs on this one formula too.

02
Not supervised

Three Ways It Differs from Supervised Learning

Rewards instead of answers, rewards that arrive late, data I change myself

① Rewards instead of answers

Supervised learning gets the answer: "in this square, go left". Reinforcement learning goes left and then gets only a score like "+1". It isn't told what going right would have earned. You can't know without trying it yourself.

② Rewards arrive late

In Go, you only know whether you won or lost after more than a hundred moves. You have to trace back and divide up which moves contributed to the win. This problem is covered with the discount rate γ and Q-Learning in 4-9.

③ My actions change the next data

Supervised learning's data was collected in advance. In reinforcement learning, the states and rewards the agent sees next depend on which action it picks. Pick only one side, and data about the other side never accumulates.

That creates a balancing act between exploration (trying the unknown) and exploitation (picking the best of what you know). You'll try it yourself in the next section.

    About the data, illustrations, and concept of this page

    • Data and calculations. The hallway cleaning bot and the reward vault probabilities (70% · 30%) are values chosen for explanation. The showdown is the average of running the same rules with 300 seeds (fixed random seed). All results are computed by this page directly in your browser. The "illustrative model" stamp on a chart means exactly this.
    • Source material. The structure of the family tree is based on the Machine Learning Algorithm Family Tree infographic (Pooja Pawar). No images were copied; only the relationships between houses, branches, and algorithms were used as a reference, and everything was redrawn.
    • Illustrations. The characters and scenes were drawn for this series. The NPCs and House crests are drawn pixel by pixel by the page itself.
    • The "Don" concept. Only the general mood of the crime-family genre is borrowed. No characters, lines, logos, or music from any specific film are used, and there is no violence. "House" is simply a metaphor for a group of algorithms.
    • Characters. AbaBot is a lab character created by the author. The Doctor, the Assistant, the Fruit Fly Researcher, and the NPCs do not represent real people. Money and investment talk in the dialogue is just a verbal habit, not investment advice.
    • Language. This series was written in Korean and translated into English, Chinese, Japanese, Uzbek, and Russian. Comments and output in the Colab code are left in the original Korean.
